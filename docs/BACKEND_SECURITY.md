# Backend Security Notes

## Implemented in this starter

- Bearer-token comparison uses constant-time comparison; protected API fails closed when `FLUXORA_API_TOKEN` is unset.
- Upload data streams in bounded chunks to opaque generated filenames. Client filename and MIME type are ignored; recognized signatures are detected from content. Default maximum upload is 50 MiB.
- Per-file paths are generated by the service and checked against the resolved private storage root. File and job lookup returns the same 404 for absent and foreign-owned identifiers.
- Download routes require ownership and emit `Cache-Control: private, no-store` and `X-Content-Type-Options: nosniff`.
- Pillow decoding has a pixel cap, rejects animated files, and output is reopened for validation. Archives have a standalone ZIP extractor with traversal, symlink, entry count, expansion size, member size, compression ratio, and encrypted-entry checks.
- The in-process worker pool is capped at four threads. Rate limiting is a process-local sliding window. There are no user-controlled subprocesses and no remote URL import endpoint (therefore no SSRF fetch path).
- File and terminal-job retention defaults to 24 hours; expired items are removed when storage/jobs are next accessed (there is no independent cleanup scheduler).
- PDF parsing has a 1,000-page cap and outputs are parser-validated. PDF endpoints execute synchronously in the API process and do not have a hard per-operation timeout or memory limit.
- Structured audit events record authentication outcome, route/method/status, and hashed principal ID; request bodies, passwords, bearer tokens, and content are excluded.

## Required before production

This application is a starter, not a hardened public service. The default job manager and file metadata are in memory; cleanup is request-triggered, not scheduled; and conversion currently buffers input/output in memory. PDF processing is synchronous. Running in a multi-process deployment loses job/ownership state. Use private durable storage plus a shared queue and ownership database, enforce disk/RAM/CPU and wall-time quotas at an isolated non-root worker/container boundary, and implement killable cancellation.

Replace the single shared API token with a proper identity provider, per-user authorization and secret rotation; use shared rate limiting and abuse controls at the gateway; add malware scanning/quarantine; restrict network egress; configure TLS, CORS, request/body limits, logging/metrics/alerting, and backup/deletion policies. Apply container seccomp/AppArmor/read-only root filesystem and writable quota-limited scratch space. Review and pin dependencies, scan images, and audit licenses.

Do not enable a processing engine until it is invoked without shell interpolation, with minimal privileges and explicit resource/deadline limits. Avoid logging tokens, document contents, or sensitive client filenames. Never expose the storage directory as a static web root.
